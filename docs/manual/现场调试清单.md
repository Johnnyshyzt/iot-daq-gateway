# 现场调试清单

版本 0.10.0。给第一次到车间的人用。没有真实机床时，可以先用 `--demo` 把模拟器跑通，再按下面的顺序换到真机。不要在清单里写口令。

## 出发前

1. 确认网关进程能打开，浏览器访问 `http://127.0.0.1:5080`。第一次仍是 HTTP，方便在没有证书时完成设置。
2. 用管理员登录。现场包的一次性口令在 `data/auth/bootstrap-password.txt`，登录后立刻改密。新密码至少 8 位，并且同时有字母和数字。
3. 打开「用户与角色」，确认至少还有一个管理员。操作员和只读账号不能改配置。
4. 打开「授权许可」，复制机器指纹给签发人。指纹包含系统标识、主机名、主板信息和网卡。只换一块网卡不会失效。
5. 打开「HTTPS」。需要加密管理口时再生成自签证书或导入 PFX/PEM，然后重启 Windows 服务、systemd 或容器。不配置就保持 HTTP。

## 接到一台设备

1. 在「设备」里选对品牌和协议，填写 IP 或主机名、端口。不要手填目录里没有的协议地址。
2. 打开「现场调试」，选这台设备，运行自检。五步分别是名字解析、端口连通、协议握手、读取样例点、耗时。
3. 失败时看该步的中文提示，不要换一套没核对过的厂商调用。常见情况：
   - 发那科 FOCAS：Windows 上要有 `Fwlib64.dll`，常见端口 8193。Linux 容器里没有这份库。
   - Modbus：核对站号 unitId，常见是 1。默认寄存器不是台达出厂表。
   - OPC UA：核对端点 URL，并把客户端证书放进对端信任列表。未受信任的证书不会自动接受。
   - 西门子：本网关走 OPC UA。如果现场实际是 S7，要另核对机架 rack 和槽位 slot，这里没有单独的 S7 驱动。
   - MTConnect：浏览器应能打开 Agent，常见路径是 `/current` 或 `/sample`。
4. 需要看报文时，先开始记录，再跑一次自检或等一个采集周期，然后在页面查看或下载。记录到时或达到大小上限会自己停。口令显示为 `***`。
5. 自检通过后，到「发布」页发布。采集读的是已发布配置。

## 离开前

1. 在「现场调试」导出诊断包，或在安装目录执行 `Host --diagnose`（Windows 是 `Host.exe --diagnose`）。包里有版本、授权摘要、打码后的配置、最近日志、链路、缓冲大小、自检和报文。没有私钥，没有登录口令，没有许可证原文。
2. 确认「审计」里能看到刚才的发布、自检和登录。
3. 把诊断包和本清单一起留给下一班。诊断包不要发到车间以外的公共位置。

## 时钟和授权异常

如果页面顶部出现时钟回拨或授权状态异常：采集不会停，但配置改不了。先把系统时间校正到不早于上次运行，再让管理员处理。不要删 `data/security` 来“重置”。
