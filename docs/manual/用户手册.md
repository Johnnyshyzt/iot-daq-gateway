# 采集网关用户手册

版本 0.11.0。界面是中文，产品名是「采集网关」。现场步骤另见 [现场调试清单](现场调试清单.md)。中心模式见 [中央管理](../central.md)。

## 1. 这是什么

采集网关跑在车间边上的一台电脑或小主机上。它按周期读取数控设备，把结果放进本机数据库，并可以送到 MQTT、HTTP、查询接口或 OPC UA。浏览器里的 Studio 和采集在同一个进程里。

没有许可证时按社区版运行。社区版的设备数、点位数和功能清单写在配置里，不是价目表。授权失败不会把正在采集的设备停掉。

## 2. 安装

Windows：解压 `win-x64` 压缩包，用管理员运行 `install-service.bat`。安装向导脚本在 `packaging/windows/iot-daq-gateway.iss`，在装了 Inno Setup 的 Windows 构建机上编译。向导会安装服务、放行 TCP 5080，并打开 `http://127.0.0.1:5080/setup`。

Linux：解压 `linux-x64` 压缩包，或按 `docs/linux-install.md` 用 systemd。Docker 使用镜像标签和数据卷，不要指望在容器里替换程序文件。

第一次打开先改掉演示口令。现场包的一次性口令在 `data/auth/bootstrap-password.txt`。

## 3. 演示数据

命令行加上 `--demo`，或在「系统」页点「载入演示数据」。会加入发那科、西门子、三菱、新代、广数、哈斯的模拟器，名称都带「演示数据」。演示数据里还有休息、节假日、理想节拍、计划停机、停机原因、一条计算点和一条主轴负载规则，以及三把刀、一次换刀和程序 O0001 的两个版本。`--central --demo` 在中心进程里写入三台边缘、一份模板的两个版本、一次配置下发和一次升级推送。这不是真实机床，也不会调用厂商 SDK。

## 4. 授权许可

打开「授权许可」。页面上有版本、用量和上限、到期时间，以及机器指纹。把指纹发给厂商，对方用 `tools/license-gen` 签发文件。私钥不在本仓库里，用环境变量 `LICENSE_PRIVATE_KEY` 或 `--key` 指向签发机上的 PEM。

导入许可证后，页面显示客户、版本和功能。所有导入、拒绝和移除都会记入审计。

到期后有一段可配置的宽限期（`Licensing:GraceDays`）。宽限期内功能仍按许可证。过了宽限期，采集继续，已有配置保持运行，但不能再把设备或点位加过社区版上限，需要授权的功能会停用。页面顶部会有提示。

默认需要授权的功能是：OPC UA 服务器、HTTP 推送、报警通知、定时报表、只读查询接口、边缘规则引擎、OEE 与停机原因、刀具寿命、NC 程序、中心管理。清单在 `Licensing:GatedFeatures`，可以改。计算点不在这份清单里，社区版可以用。

## 5. 升级

在「升级」页上传 zip。包里要有 `SHA256SUMS` 和用产品公钥签过的 `SHA256SUMS.sig`，以及 Host 程序和 `wwwroot/index.html`。校验通过后，网关先备份数据库，再把包暂存下来。正在运行的进程不会替换自己。

然后重启 Windows 服务或 systemd。`apply-upgrade.ps1` / `apply-upgrade.sh` 在进程退出后覆盖安装目录（不含 `data`）。失败时从 `data/upgrade/previous` 恢复程序，并可以从页面把数据库恢复到升级前的备份。

Docker 请更换镜像标签后重建容器。仓库里没有私钥，所以 GitHub Release 只有在配置了 `RELEASE_SIGNING_KEY` 时才会带上签名。没有签名的包不能从页面安装，仍可以手工解压替换。

## 6. 备份

SQLite 是默认库。「系统」页可以下载一致的快照，或从该文件恢复。恢复前会留下 `gateway.db.bak`。页面备份不含登录口令。

PostgreSQL 在本机 PATH 里有 `pg_dump` 和 `pg_restore` 时，同一页可以导出和恢复。找不到工具时会提示安装客户端，不会假装已经备份。

## 7. 采集和北向

设备、点位模板和发布方式与之前的版本相同。发布之后采集才加载新配置。MQTT 仍是默认北向。HTTP 推送、查询接口和 OPC UA 在授权允许时可用。查询接口使用只读密钥，不明文保存。

厂商 SDK（例如发那科 FOCAS）要自己准备，本仓库不附带。

## 8. 结构版本

数据库结构版本是 9。从 1 到 8 的库会在启动时补上许可证、安全状态、自检、计算点、规则、停机原因、OEE、刀具、NC 程序和中心管理用到的表，不需要手工迁移。中心和边缘各用自己的数据库，结构版本相同。

## 9. 现场调试

「现场调试」里可以选择设备做连通性自检，查看报文，并导出诊断包。清单全文在 [现场调试清单](现场调试清单.md)。没有真实机床时，模拟器会说明各阶段为什么通过。

## 10. 账号和 HTTPS

管理员在「用户」里维护账号。工程师可以改配置。操作员可以给停机记录填写原因、批量指定原因，登记报废，记录换刀和手动加件数，不能改原因树、班次、规则、计算点、刀具主数据或程序库。只读只能看。批准 NC 程序、签发注册令牌和暂存升级包需要管理员。连续输错密码会锁定一段时间。

「HTTPS」可以生成自签证书、导入证书或关闭。第一次安装仍用 HTTP，改完要重启 Windows 服务、systemd 或容器。

## 11. 计算点

打开「计算点」。一条计算点属于一台设备，或属于一个点位模板。表达式只能使用四则运算、比较、并且 / 或者 / 非，以及白名单函数：`if`、`abs`、`min`、`max`、`round`、`delta`、`rate`、`avg`、`durationTrue`、`counterInc`、`since`。也有中文别名。不能写分号、花括号或调用任意代码。

点位 Id 以字母或下划线开头。「实时预览」用所选设备的当前值和最近一小时历史算出结果。保存前会校验表达式。启用后，计算点跟普通点一样进历史、MQTT、HTTP 和 OPC UA，报文里多一个 `computed: true`。OPC UA 显示名会带「（计算）」。

## 12. 边缘规则

打开「边缘规则」。条件是同一套表达式。持续时间表示条件要连续成立这么久才动作；中途变假会重新计时。防抖是触发之后的一段抑制时间。进程重启后，持续和防抖重新计算。

动作可以是：产生报警、触发一条已有通知通道、写入一个数值、发出北向事件（MQTT 主题 `$event`）、或给当前还没填原因的停机自动指定原因编码。

页面上有三条模板：主轴负载超过 90% 持续 5 分钟、由产量计数得到节拍、空闲超过设定分钟。「按最近历史回测」用约 6 小时历史重放，不写报警。执行记录只在真正触发时写入。

没有 `rules` 授权时可以打开页面看模板，不能保存、删除或回测，采集也不会执行规则。

## 13. OEE 和停机原因

OEE = 可用率 × 性能率 × 质量率。

- 计划生产时间：班次与查询窗口重叠的部分。没有配置休息时，用班次上的计划分钟（默认白班、夜班各 660 分钟）。配置了休息之后，计划时间改为班次长度减去休息，不再使用计划分钟，避免减两次。节假日当天计划时间为 0。计划停机（日历上的时段，以及状态为计划停机的时段）再从计划时间里扣除，重叠部分只扣一次。
- 可用率 = 运行时间 / 计划生产时间。计划生产时间为 0 时，可用率和 OEE 记为 0，标记 `noPlannedTime`。
- 性能率 = 理想节拍秒 × 总产量 / 运行秒。理想节拍按设备配置，程序名一致时用该程序，否则用程序名为空的默认节拍。一个班次窗口只用最后一次程序名，不按程序分段加权。没有理想节拍时，性能率和 OEE 留空，标记 `missingIdealCycle`。
- 质量率 = (总产量 − 报废) / 总产量。报废来自点位 `scrapCount`（可用设置 `oee.scrapPoint` 改名）的增量，加上手工登记。总产量为 0 且没有报废时，质量率记为 1。
- 三个比率相乘前都限制在 0 到 1。

「OEE」页按设备、产线、班次或日查看，有损失瀑布、停机原因帕累托和趋势，可导出 CSV 或 Excel。定时报表在授权允许时附加平均 OEE。查询接口 `GET /api/query/v1/utilization` 仍是 `northbound/1.0`；授权允许时，每台设备多可用率、性能率、质量率、OEE 和标记，没有这些字段的旧报文仍然有效。

「停机原因」列出非运行状态形成的停机段。默认原因树是中文的计划、故障、物料、人员和其他。操作员填写原因；工程师可以增删原因，也可以批量指定。规则可以按原因编码自动填写尚未指定的记录。

「班次日历」维护班次、休息、节假日、计划停机、理想节拍和状态映射。状态映射按设备、模板、品牌的顺序覆盖默认分类。

没有 `oee` 授权时，「OEE」页说明未授权，不给出报表。CSV 和 Excel 会被拒绝。

## 14. 刀具寿命和 NC 程序

「刀具寿命」维护刀号、说明、件数上限和/或切削分钟上限，以及预警百分比。每台设备可以登记刀位里当前装的刀。

累计只使用驱动或模拟器已经提供的点：刀号、件数、累计件数、状态、是否运行、节拍。第一次见到这把刀只记下基线，不把机床上已经累计的件数算进新刀。之后件数按增量增加。切削时间按运行状态的时间间隔计算，单次间隔最多 2 分钟，节拍增量同样封顶。现有驱动没有刀号的品牌，页面上会写明，改用手动加件数，或用计算点写出 `toolNumber` 和 `partCount`。

达到预警百分比时产生报警代码 `TOOL-WARN`，达到上限时产生 `TOOL-EOL`。报警进入原来的报警列表和通知。操作员记录换刀，可以选择把该刀在这台设备上的寿命清零。工程师维护主数据。CSV 报表在「刀具寿命」页导出。

「NC 程序」保存程序和版本。上传后是草稿。工程师可以再上传一版并看差异。管理员批准或归档。校验和是把换行收成 `\n` 之后的 SHA-256。每次上传、下载、批准和下发都写入审计。

下发只走三类已经实现的路径：设备参数或请求里的 DNC 目录、已经挂载好的共享目录、以及现有 FTP 驱动的上传和下载。海德汉 LSV2 驱动目前只读参数，页面标成不能下发程序，本版本不补厂商文件命令。其他品牌的厂商 SDK 同样不发明调用。未批准的版本会被拒绝，返回 `program_not_approved`。

没有对应授权时，两个页面说明未授权，不返回明细。

## 15. 多网关中心

同一套 Host 加上 `--central`（或 `Host:Mode=central`，或环境变量 `HOST_MODE=central`）变成中心，不再采集。边缘在 `Central:Url` 配好中心地址后，用注册令牌主动连出。令牌只在创建时显示一次，库里存的是哈希。会话是带 HMAC 的令牌，走 HTTPS。产品不自建证书中心；若要双向 TLS，在前面的反向代理上终结。

心跳带上版本、许可证摘要、设备数、链路健康和内存。中心用最近一次心跳做机队列表，并在超时后告警。点进一台网关看到的是这份摘要，不是反向隧道。

配置模板有版本。下发时带差异，可以按分组或指定网关，也可以回滚到上一版。冲突策略：

- `central-wins`：覆盖中心管理的内容，并清掉本地脏标记。
- `local-wins`：边缘把文档标脏之后，中心跳过。

模板可以声明 `managed` 和 `local`。连接地址、端口、口令、显示名、用户、许可证和 HTTPS 始终由现场管理，中心不覆盖。标识以 `central-` 开头的规则由中心写入。点位模板和通知设置先作为文档保存；本版本会把规则写进边缘规则表，不把点位和通知整份合并进采集配置。

升级包仍是原来的 ES256 签名 zip。中心暂存后，选中的边缘在心跳里领取并在本机暂存，不在运行中替换程序。进度和失败记在推送目标上。

中心进程需要 `central` 功能。每台边缘继续用自己的许可证判断刀具、程序和其他功能。中心连不上时，边缘采集、报警和本地配置保持原样。

示例编排是 `docker/compose.central.yml`：一台中心加三台模拟边缘。
